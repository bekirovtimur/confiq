# План устранения проблем с QR-кодами

## Цель

Предлагать QR-код только тогда, когда конфигурацию можно закодировать с ограниченной плотностью и показать в размере, удобном для сканирования. Большие конфигурации должны оставаться доступными для просмотра, копирования и скачивания независимо от доступности QR.

Абсолютно гарантировать чтение любой камерой невозможно: результат зависит от экрана, освещения, камеры и приложения. Задача изменений — исключить переполнение генератора, слишком плотные изображения и ухудшение читаемости из-за масштабирования.

## Реализация

- Общая логика находится в `utils/qr.py`: предел версии `15`, коррекция `M`, белое поле `4` клетки.
- Все пользовательские QR-действия используют одну проверку. Для неподходящих конфигураций кнопки скрыты, прямой запрос PNG возвращает HTML-ответ `422` со ссылкой на скачивание.
- QR показывается с размером клетки `4` CSS px или `3` CSS px в более узком контейнере. Если контейнер уже `255` CSS px, вместо уменьшенного изображения предлагается открыть его в полном размере.
- Готовые PNG с конфигурационными секретами отправляются с `Cache-Control: private, no-store`.
- Добавлены модульные и интеграционные тесты в `tests/test_qr.py` и `tests/test_qr_routes.py`. Запуск из корня проекта после установки `requirements.txt`:

```bash
python -m unittest discover -s tests -v
```

Тесты используют отдельную SQLite-базу в памяти и не импортируют `app.py`, чтобы не запускать инициализацию рабочей базы `/data`.

Ограничение версии 15 намеренно исключает часть AmneziaWG-конфигураций. Например, образец на 450 байт в байтовом режиме уже не помещается в 15-M; для него нужно использовать файл. Менять предел следует только после проверки более плотных QR на целевых устройствах и пересмотра порогов отображения в CSS.

## Текущее поведение и причины проблемы

- В `routes/user.py` генерация дублируется в `generate_qr_code()` и обработчике `config_qr()`.
- В обоих местах вызывается `qr.make(fit=True)` без обработки переполнения. Библиотека автоматически увеличивает версию QR. Если требуется версия выше максимальной допустимой — 40, возникает исключение. Наблюдаемая ошибка: `ValueError: Invalid version (was 41, expected 1 to 40)`.
- `view_config()` генерирует QR при каждом открытии конфигурации. Поэтому переполнение ломает не только получение картинки, но и всю страницу просмотра.
- В `templates/user/view_config.html` изображение ограничено `max-width: 200px`. При большом количестве клеток такое уменьшение делает QR неудобным для сканирования и может размывать границы клеток.
- На главной странице, в списке конфигураций и на странице просмотра QR предлагается без проверки доступности.
- Запасная инструкция в `templates/user/view_config.html` безусловно предлагает сканирование «QR-кода выше».

## 1. Общая политика генерации

Вынести проверку вместимости и генерацию QR в отдельный модуль, например `utils/qr.py`. Оба существующих сценария должны использовать его, а не независимо создавать `qrcode.QRCode`.

Начальные параметры для проверки на реальных устройствах:

| Параметр | Предлагаемое значение |
| --- | --- |
| Коррекция ошибок | `ERROR_CORRECT_M` |
| Максимальная версия | `15` |
| Цвета | Чёрный на белом |
| Белое поле | `4` клетки с каждой стороны |
| Размер клетки в PNG | Целое число пикселей, например `6` |
| Размер клетки при показе | Желательно `4` CSS px, не менее `3` CSS px в обычном представлении |

Версия 15 — начальный консервативный предел, а не универсальная граница читаемости. Его нужно подтвердить на типичных конфигурациях и целевых телефонах. Ограничение может скрыть QR и для некоторых конфигураций, которые технически помещаются в стандартный QR: это ожидаемый компромисс в пользу удобства сканирования.

Повышение коррекции ошибок с `L` до `M` уменьшает вместимость. Оно не заменяет контроль плотности и корректное отображение.

Все параметры должны задаваться в одном месте. Миграция базы данных для этого не требуется.

## 2. Безопасная проверка вместимости

Реализовать следующий алгоритм:

1. Создать QR с общей политикой коррекции ошибок и добавить исходный текст конфигурации.
2. Проверять версии от `1` до максимально разрешённой включительно, вызывая `make(fit=False)`.
3. При `qrcode.exceptions.DataOverflowError` переходить к следующей разрешённой версии.
4. При первом успехе вернуть результат с подготовленным QR и параметрами для отображения. Так выбирается минимальная подходящая версия без повторной генерации перед формированием PNG.
5. Если не подошла ни одна разрешённая версия, вернуть результат «QR недоступен», не создавая изображение.

Использование ограниченных версий с `fit=False` исключает автоматический переход к версии 41. Не следует заменять это общим `except Exception` или подавлением любых `ValueError`: так можно скрыть ошибки программирования.

Дополнительные требования:

- Проверять фактическую вместимость средствами библиотеки, а не только `len(text)` или порогом количества символов. На вместимость влияют UTF-8 и режим кодирования.
- Не изменять содержимое конфигурации ради вместимости: не обрезать текст, не удалять параметры и не применять сжатие, которое клиент не поддерживает.
- Для пустого содержимого возвращать «QR недоступен».
- Проверку доступности выполнять без создания PNG и base64.
- Использовать одинаковые параметры кодирования при проверке и при построении изображения.
- Не записывать текст конфигурации, приватные ключи или изображение QR в логи. При необходимости логировать только техническую причину отказа и идентификатор конфигурации.

## 3. Интеграция с маршрутами

Изменить `routes/user.py`:

- `dashboard()` и `configs()`: передавать в шаблоны доступность QR для отображаемых конфигураций. Для списка с пагинацией проверять только элементы текущей страницы.
- Не выполнять одинаковую проверку отдельно для каждой кнопки одной конфигурации: рассчитать результат один раз на конфигурацию в рамках запроса.
- `view_config()`: генерировать изображение только при положительном результате проверки; в остальных случаях передавать признак недоступности и понятную причину.
- `config_qr()`: применять ту же политику, даже если пользователь пришёл по прямой или ранее сохранённой ссылке.
- При недоступном QR возвращать из `config_qr()` понятный ответ с HTTP `422`, например HTML-страницу с объяснением и ссылкой на скачивание файла, а не ошибку `500`.
- Сохранить `login_required` и проверку принадлежности конфигурации текущему пользователю. Проверять доступ до анализа содержимого конфигурации.
- Удалить дублирующую реализацию генерации после перевода обоих сценариев на общий модуль.

Создание и сохранение самой конфигурации не должны зависеть от возможности построить QR.

## 4. Условное отображение в интерфейсе

Обновить шаблоны:

- `templates/user/dashboard.html` — скрывать пункт QR в меню и кнопку QR в карточке, если QR недоступен.
- `templates/user/configs.html` — аналогично скрывать оба действия.
- `templates/user/view_config.html` — показывать изображение и кнопку полного размера только при доступном QR.

На странице просмотра вместо недоступного QR вывести сообщение:

> Конфигурация слишком большая для удобного сканирования. Скачайте файл и импортируйте его в приложение.

Для пустого содержимого использовать отдельное объяснение, не называя его слишком большим.

Рядом с объяснением оставить доступное действие скачивания. В запасной инструкции по импорту предлагать сканирование только при наличии QR; в противном случае описывать импорт из файла. Не скрывать остальные информационные блоки вместе с QR-карточкой.

## 5. Исправление размера изображения

Изменить `templates/user/view_config.html` и стили `.qr-container` в `static/css/style.css`:

- Убрать ограничение `max-width: 200px`.
- Рассчитывать размер изображения по количеству клеток с учётом белого поля.
- Использовать целое число CSS-пикселей на клетку и избегать произвольного уменьшения браузером.
- Сохранять квадратные пропорции и белое поле; не обрезать изображение и его края скруглением.
- Проверить внутренние отступы карточки: они не должны вынуждать уменьшать QR ниже выбранного размера.
- На узких экранах предусмотреть отдельное просторное представление или полноэкранный просмотр. Не показывать заведомо слишком мелкий QR как обычный способ импорта.

Пример: версия 15 содержит 77 × 77 клеток. С полем по 4 клетки получается 85 × 85 клеток. Для отображения нужны 255 × 255 CSS px при 3 px на клетку или 340 × 340 CSS px при 4 px на клетку.

Размер PNG сам по себе не гарантирует читаемость: важен фактический размер изображения после применения CSS и ограничений контейнера.

## 6. Проверки и тесты

До изменений тестовых файлов в проекте не было. Для проверки общей логики и маршрутов используются модульные и интеграционные тесты. Использовать синтетические конфигурации без настоящих ключей и отдельную тестовую БД, не затрагивая рабочую базу.

### Автоматические проверки

- Маленькая конфигурация: QR доступен, изображение формируется.
- Подбирается минимальная подходящая версия, не превышающая установленный предел.
- Данные на границе вместимости и сразу за ней: корректное решение о доступности.
- Очень большой текст, включая случай, ранее приводивший к попытке версии 41: ожидаемый отказ без исключения наружу.
- UTF-8, включая кириллицу: решение принимается по реальному кодированию, а не числу символов.
- Пустой текст: QR недоступен.
- Страница большой конфигурации отвечает `200`; просмотр и скачивание продолжают работать.
- При недоступности QR отсутствуют все соответствующие кнопки, пункты меню и инструкции по сканированию на главной странице, в списке и при просмотре.
- Прямой запрос `/user/configs/<id>/qr` для неподходящей конфигурации возвращает `422` с понятным объяснением.
- Для подходящей конфигурации этот маршрут возвращает корректный PNG с `Content-Type: image/png`.
- Проверки входа и владения конфигурацией сохраняются.
- Если в тестах используется QR-декодер, результат декодирования в точности совпадает с исходным текстом. Декодирование не заменяет проверку реальной камерой.

### Ручные проверки

- Типичные конфигурации WireGuard и AmneziaWG, прошедшие ограничение вместимости, сканируются целевыми приложениями. Для остальных корректно предлагается импорт из файла.
- Проверены QR близко к разрешённому пределу, а не только самые маленькие.
- Проверены обычный и полноэкранный режимы, узкий экран и светлая/тёмная тема.
- Изображение не размывается, не обрезается и сохраняет белое поле.
- Для слишком больших конфигураций понятен путь импорта из файла.

## Критерии готовности

1. Переполнение QR больше не приводит к `500` при просмотре конфигурации и запросе изображения.
2. Используется единая политика вместимости и плотности для всех QR-действий.
3. Неподходящие конфигурации не предлагают QR ни в одном из пользовательских разделов.
4. Доступные QR показываются без чрезмерного уменьшения и проверены на реальных устройствах.
5. Содержимое конфигураций и действующие ограничения доступа не изменены.
6. Просмотр, копирование и скачивание работают независимо от доступности QR.
