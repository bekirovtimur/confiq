# Confiq

Универсальный менеджер конфигураций с гибкой системой шаблонов.

> **📝 Примечание:** Confiq — это инструмент для управления конфигурациями, который может быть использован с различными API. В данном репозитории в качестве примера реализована интеграция с Cloudflare API для работы с WARP конфигурациями.

## ⚠️ Важная информация

**Автор проекта не связан с компанией Cloudflare.** Использование публичного API Cloudflare для создания и управления конфигурациями WARP представлено исключительно в **ознакомительных и образовательных целях**.

## 🚀 Основные возможности

### Для пользователей
- ✅ Создание конфигураций различных типов (WireGuard, AmneziaWG, Clash)
- ✅ Просмотр конфигураций с QR-кодами для подходящего объёма данных
- ✅ Скачивание конфигураций в форматах `.conf` и `.yaml`
- ✅ Управление своими конфигурациями
- ✅ Ограничения на количество конфигов на пользователя

### Для администраторов
- ✅ Управление пользователями
- ✅ Управление endpoints для подключения
- ✅ Управление типами конфигураций с шаблонами Jinja2
- ✅ Счётчик использования типов и удаление типов без конфигураций
- ✅ Настройка поддерживаемых типов для каждого endpoint
- ✅ Общий список конфигураций с владельцем, типом, endpoint и датой создания
- ✅ Просмотр, скачивание и QR-коды конфигураций любых пользователей
- ✅ Смена типа существующей конфигурации с сохранением ключей и IP-адресов
- ✅ Массовые операции с конфигурациями

## 📦 Быстрый запуск

```bash
# 1. Клонирование репозитория
git clone https://github.com/bekirovtimur/confiq.git
cd confiq

# 2. Настройка .env файла
cp .env.example .env
# Отредактируйте .env, укажите CADDY_DOMAIN, CADDY_EMAIL, ADMIN_PASSWORD, SECRET_KEY

# 3. Запуск
docker compose up -d
```

Приложение будет доступно по HTTPS через несколько минут.

**Подробная инструкция:** [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)

## 📚 Использование

### Для администратора

1. Войдите в систему (`/auth/login`)
2. Создайте типы конфигураций (Панель управления → Типы конфигураций)
3. Создайте endpoints (Панель управления → Endpoints)
4. Создавайте пользователей (Панель управления → Пользователи)
5. Откройте **Все конфигурации** (`/admin/configs`), чтобы увидеть конфиги всех пользователей
6. Используйте действия **Просмотреть**, **Скачать** и **Изменить тип** в строке конфигурации

При смене типа доступны только другие активные типы, поддерживаемые текущим endpoint. Файл генерируется заново из сохранённых данных без обращения к Cloudflare; владелец, название, endpoint, ключи и IP-адреса не меняются. При ошибке исходный конфиг сохраняется.

**Важно:** после смены типа нужно заново скачать файл и импортировать его в подходящий клиент. Старые файлы не обновляются и не отзываются. Поддержку протокола и его параметров сервером необходимо проверить отдельно.

Подробности, ограничения и проверка результата: [управление конфигурациями администратором](docs/ADMIN_CONFIGS.md).

На странице **Типы конфигураций** (`/admin/config-types`) показано количество конфигов каждого типа среди всех пользователей. При нулевом количестве доступно удаление с подтверждением: привязки типа к endpoints удаляются, сами endpoints сохраняются. Используемый тип удалить нельзя — сначала смените тип связанных конфигураций. Стандартные шаблоны добавляются только при создании таблицы типов, поэтому удалённые типы не восстанавливаются при перезапуске.

### Для пользователя

1. Войдите в систему
2. Создайте конфигурацию: выберите endpoint и тип
3. Скачайте файл конфигурации или отсканируйте QR-код

В форме создания endpoints отсортированы по названию без учёта регистра. Если доступ ограничен группой, сортируются только endpoints этой группы.

QR-код доступен только для конфигураций, которые помещаются в установленный предел плотности (версия QR не выше 15, коррекция ошибок M). Для более объёмных конфигураций кнопки QR скрыты — используйте скачивание и импорт файла. Подробности: [ограничения и проверка QR-кодов](docs/QR_CODE_FIX_PLAN.md).

### Запуск тестов

Создайте виртуальное окружение и выполните из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B -m unittest discover -s tests -v
```

Тесты маршрутов используют SQLite в памяти и не импортируют `app.py`, поэтому не затрагивают рабочие конфигурации и `/data`. Административные сценарии проверяются в `tests/test_admin_configs.py`, логика QR — в `tests/test_qr.py` и `tests/test_qr_routes.py`. Ключ `-B` предотвращает создание файлов байткода при запуске тестов в свежем окружении.

Правила работы с кодом и тестами для агентов: [`AGENTS.md`](AGENTS.md).

## 🔌 API Endpoints

| Метод | Endpoint | Описание |
|-------|----------|----------|
| GET/POST | `/auth/login` | Вход в систему |
| GET | `/auth/logout` | Выход из системы |
| GET | `/user/dashboard` | Панель пользователя |
| GET | `/user/configs` | Только конфигурации текущего пользователя |
| GET/POST | `/user/configs/create` | Создание конфигурации |
| GET | `/user/configs/<id>` | Просмотр своей конфигурации |
| GET | `/user/configs/<id>/download` | Скачивание своей конфигурации |
| GET | `/user/configs/<id>/qr` | QR своей конфигурации; `422`, если QR недоступен |
| GET | `/admin/dashboard` | Панель администратора |
| GET | `/admin/config-types` | Типы конфигураций |
| POST | `/admin/config-types/<id>/delete` | Удаление типа, не используемого конфигурациями; требуется CSRF |
| GET | `/admin/configs` | Все конфигурации, по 10 на страницу (`?page=N`) |
| GET | `/admin/configs/<id>` | Просмотр конфигурации любого владельца |
| GET | `/admin/configs/<id>/download` | Скачивание конфигурации любого владельца |
| GET | `/admin/configs/<id>/qr` | QR конфигурации любого владельца; `422`, если QR недоступен |
| GET/POST | `/admin/configs/<id>/change-type` | Форма и сохранение нового типа конфигурации |

Это маршруты веб-интерфейса, а не отдельный JSON API: они используют сессию входа, а форма смены типа — CSRF-токен. Маршруты `/admin/*` требуют прав администратора. Пользовательские обработчики конфигураций проверяют владельца, в том числе при входе под администратором; для чужих конфигураций используйте `/admin/configs/<id>`.

## 🛠 Технологии

- **Backend**: Python 3.11, Flask, SQLAlchemy, Flask-Login
- **Frontend**: HTML5, собственные CSS/JavaScript в стиле Material Design, Jinja2
- **База данных**: SQLite
- **Reverse Proxy**: Caddy (с автоматическим SSL через Let's Encrypt)
- **Контейнеризация**: Docker, Docker Compose

## 👥 Группы пользователей

В системе реализована поддержка **групп пользователей** для управления доступом к endpoints.

### Как работают группы

- Каждый пользователь может быть назначен в группу (или оставаться без группы)
- Группы определяют, к каким endpoints имеют доступ пользователи
- Администратор может привязать endpoints к группам
- Пользователи видят и могут создавать конфигурации только на доступных им endpoints

### Управление группами

1. Создайте группы в панели администратора (Панель управления → Группы)
2. Назначьте пользователей в группы при создании/редактировании пользователя
3. Привяжите endpoints к группам при создании/редактировании endpoint

## 🔄 Миграция с предыдущих версий (до появления групп)

⚠️ **ВАЖНО: Перед миграцией обязательно сделайте резервную копию базы данных!**

```bash
# Создание бэкапа
cp data/warp_manager.db data/warp_manager.db.backup.$(date +%Y%m%d_%H%M%S)
```

Если вы используете старую версию без поддержки групп, выполните миграцию:

```bash
# Запуск миграции
python3 migrations/migrate_add_groups.py data/warp_manager.db
```

Миграция создаст:
- Таблицу `groups` для хранения групп
- Колонку `group_id` в таблице `users`
- Таблицу связи `group_endpoints` для привязки endpoints к группам
- Таблицу связи `endpoint_config_types` (если отсутствует)

После миграции все существующие пользователи будут без группы (доступ ко всем endpoints).

## 📝 Информационный баннер

На страницах пользователей отображается информационный баннер, который можно использовать для размещения важных объявлений, информации о поддержке проекта или других сообщений.

### Где отображается баннер

Баннер отображается на следующих страницах:
- **Панель пользователя** (`/user/dashboard`) — над блоком "Быстрые действия"
- **Список конфигураций** (`/user/configs`) — под статистикой, над списком конфигураций
- **Просмотр конфигурации** (`/user/configs/{id}`) — под QR-кодом

### Редактирование содержимого баннера

Содержимое баннера хранится в файле [`info.html`](info.html) в корне проекта. Файл поддерживает HTML-разметку, что позволяет:
- Форматировать текст (жирный, курсив, заголовки)
- Добавлять ссылки
- Создавать списки
- Использовать стили

### Включение и отключение баннера

Отображение баннера управляется переменной окружения `INFO_BANNER` в файле `.env`:

```bash
# Включить баннер (значение по умолчанию)
INFO_BANNER=true

# Отключить баннер
INFO_BANNER=false
```

После изменения переменной окружения необходимо **перезапустить контейнеры**:

```bash
docker compose restart
```
